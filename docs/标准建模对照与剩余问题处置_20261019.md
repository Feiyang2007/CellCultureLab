# 标准建模对照与剩余问题处置

日期：2026-10-19。本次为源码及官方案例审计，未修改已验资产，也未开展新的运行时容量实验。

## 结论与证据边界

此前确有转换语义错误和近似绕行。C1 测量修复仍有效；v5 的 21/21 仅证明分批、零重力、禁接触、注入驱动条件下的方向及端点约束，不证明原任务或跨引擎动力学等价。当前 v5 应保留为诊断基线。

### 已确认缺口

- v4 错误关节类型、API 缺失及坐标轴问题，详见《运行时测量与v5修复_20261019.md》。
- 当前真值导出器没有导出完整惯量及惯性坐标系、执行器定义、显式接触对/排除、等式约束和任务脚本行为；质量与初始几何正确不能替代这些信息。
- v5 仅把 contype/conaffinity 转成“是否建立碰撞体”，没有迁移碰撞配对过滤规则。六台真值的接触形状全部为 contype=0、conaffinity=1（5430 有 1994 个）。两个此类形状按 MuJoCo 自动配对规则不会接触；显式 pair 可例外。必须结合完整任务里的其他物体、pair/exclude 和过滤选项重新导出，不能简单删除所有接触。
- 涡旋辅助刚体惯量补偿是近似。安装的 PhysX 107.3 schema 已提供原生 physxJoint:armature，但仅在 Articulation 中生效。应先验证原生结构，再决定辅助体与参数。
- W3 的实测来自旧 v06 场景。不能把新发现的 v5 过滤遗漏直接定为旧场景溢出根因，须审计旧场景并做配对对照。

### 尚未证明

碰撞过滤遗漏、初始穿插、复杂碰撞体、接触距离及旧资产结构可能共同增加接触负担，目前没有隔离实验证明各自贡献。增加两个容量后仍存在其他溢出，不能据此认定只需继续扩容或硬件不足。

## 处理顺序与验收

1. 冻结诊断基线，补全 MuJoCo 真值导出（含完整任务的过滤、惯量、执行器与状态机）。建立“保留/近似/缺失”映射表。
2. 用 mini 的盖子/转子做固定底座 Articulation 试点，正确 world FixedJoint 与根节点、真实惯量及原生 armature。比较相同重力、初态和输入下的角度、速度、稳态与外力响应；保留当前隔离测量作为回归项。不同引擎不要求逐步数值相同，误差范围应按任务需求明确。
3. 先还原接触语义；用“单设备→单管/单孔→小架→1/8/32/96 个吸头→房间”逐级实验，记录允许/实际接触对、穿插、步耗时及内存。碰撞几何简化须保留操作孔洞；检查 contactOffset 与物理尺度。
4. 在几何与过滤正确后按最坏工况统计设置 GPU 容量。验收要完整运行、无丢弃接触/约束警告，不能仅凭属性读回或进程未退出。
5. W4 先做单管单孔插入/拔出及碰壁对照，再扩展 30 孔；W5 迁移 C1000 detent/锁盖状态及物理约束，验证锁住时施加外力仍不能打开、解锁后可开。
6. C2 按覆盖矩阵中的下一条任务选择具明确许可的模型，补交互和成功条件；W2 标记并替换占位纹理，未经明确接受不作为真实视觉内容验收；W6 在上述实验统一采集 committed/private bytes、显存和崩溃时间，继续定位，保持分页配置不变。
