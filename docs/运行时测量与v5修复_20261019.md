## 已确认的根因

1. v4 的 17 个 RevoluteJoint 和 4 个 PrismaticJoint 使用了错误的 USD 类型名。现场用官方 schema 的 IsA 检查，21 个都不属于 UsdPhysics.Joint；正确类型是 PhysicsRevoluteJoint / PhysicsPrismaticJoint。名称相似、关系和 drive 属性存在，不能说明 PhysX 创建了关节。
2. 六台资产均未应用 PhysicsDriveAPI；27 个刚体均未应用 PhysicsMassAPI。裸写 physics:mass / drive:* 属性不能替代 API。
3. 49 个 Box 不是有效 USD Cube。此前所谓“Box/Cylinder/Sphere schema 未注册”的解释不成立；变换校验通过只证明 holder 的坐标，未证明形状或物理类型正确。
4. 关节缺 localRot0/1，且把真值轴取绝对值后选最近主轴，丢失了负轴、斜轴及父子坐标差异。C1000 lid 的旧 frame 甚至让 twist 无法定义。
5. 旧测量脚本另有轴索引父/子名字不一致（20/21 不匹配）、四元数顺序错误、滑动关节按角度判定、单侧限位给非法负目标、正反测试未重置等问题。

## 已落盘的实现

- scripts/check_actuation_direction.py：用 RigidBodyView.get_transforms 读取 xyz+xyzw；两侧运行时刚体姿态结合 localPos/localRot 计算关节坐标。转动为度，滑动为米。缺读数、非法 schema、未到参考位、参考态不稳均独立报告。
- scripts/runtime_joint_math.py 与 scripts/test_runtime_joint_math.py：17 个数学测试通过，覆盖正负转角、q/-q、父子共同转动、局部关节 frame、滑动锚点、单侧限位及禁止的锚点/角度偏差。
- scripts/mjcf_instrument_to_usd_v5.py → assets/instruments5/：正式 joint/drive/mass schema、有符号轴对齐的两侧 frame、正确 Cube 尺寸与图元数值类型、MuJoCo mesh 的 convexHull 碰撞近似、焊接子体 FixedJoint；不在单件资产内生成 PhysicsScene。
- assets/scenes/test_instruments5.usda：六台 v5 的独立测试场。v4 和主场景原件保留。
- scripts/check_v5_independent.py：直接对 upstream/truth 原始向量做几何、锚点、轴向及 schema 检查。

## 已有证据及适用范围

- 最小已知铰链：±20° 指令测得 ±19.482987°，关闭驱动的对照为 0°；位置全程不变。见 outputs/runtime_validation/sensor_calibration.json。
- v5 独立检查：六台 2180 个 geom 全部核对；28 个 MassAPI（27 个源刚体加 1 个串联辅助体）；21 个正式可动关节和 1 个 C1000 焊接关节；宿主仅 1 个 PhysicsScene；轴向残差 <4e-8，锚点残差 <8e-6 mm。见 v5_independent.json。
- 首轮完整隔离实验：19 个方向性确认，2 个参考态速度未降到阈值，因此明确不计通过。两个分别是 5910 的 rotor_bucket_2_adapter_7x50_1 和 C1000 的 lid_lid_lever。见 actuation_v5_all_isolated.json。这轮使用的是图元数值类型最后规范化前的 v5，后续最终复测单独保存。

所有上述方向实验均为 CPU、零重力、禁用接触、临时驱动；它们不证明正常接触下可开盖、插管、抓取，亦不证明与 MuJoCo 动力学等价。

### 最终运行证据（按当前资产版本筛选）

- 非涡旋的 17 个关节：actuation_v5_final_zero_velocity_20261019.json，清零初速后正/负/保持对照通过；actuation_v5_final_constraints_20261019.json 独立核对当前资产哈希和端点约束。
- 涡旋同体的 platform/pivot 与 platform/orbit 必须串联；早期 v5 的并联版本虽有转角，但 orbit 锚点误差达 0.587 mm，已排除出最终证据。
- 最终涡旋：辅助体放在源 pivot 锚点上，将源平台质量的 1% 分到辅助体以保持总质量，并用轴向惯量近似其 0.1 armature。较早串联试验发生明显约束漂移，相关失败报告保留，不计通过。
- 最终复测文件：actuation_v5_vortex_anchored_20261019.json 与 actuation_v5_vortex_anchored_constraints_20261019.json。四关节通过正/负/保持、零初速及端点约束；使用 1/240 s、600 步参考位预热、480 步指令、angular stiffness=20、damping=2、maxForce=1、32 次求解迭代。
- 汇总是 **17+4 分批验证**，不是一次整场运行。build_runtime_acceptance.py 重新核对当前目标资产哈希、21 个预期关节和所有结果，得到 verified=21、missing=0、failed=0。
- 约束阈值：参考位和终点的禁止位移 ≤0.1 mm、禁止角偏差 ≤1°；未声称全轨迹约束已验。主检查器现在也会将超阈值标成 CONSTRAINT_VIOLATION，避免“转得动就算成功”。

## W3 容量配置

静态定位已成立：v07 两项 aggregate 容量被写成 int，当前安装 schema 要 uint；v4 迷你场有 7 个 PhysicsScene，默认首个没有容量，而六件资产内部 scene 的容量不会自动作用于首个 scene。根路径 /physicsScene 合法，缺显式重力不是已证根因。

scripts/validate_gpu_capacity.py 可审计与在 session 层修复：选择一个宿主 scene、正式应用 PhysxSceneAPI、uint 8192 两项容量、显式 simulationOwner，并导出新覆盖层。静态结果见 outputs/runtime_validation/gpu_capacity_*_fixed.json / .usda。

### 2026-10-19 的 GPU 实测

移除 Python 日志回调后，本地 v06 派生场实际完成 600 步 GPU 基线。日志确认接触丢失，报告的最低需求为：total aggregate pairs 1025、found/lost aggregate pairs 6700、rigid patches 141733、collision stack 1848565400 bytes。证据：gpu_v06_local_baseline_filtered_20261019.log 与 gpu_v06_local_baseline_reviewed_20261019.json。

随后仅把两项 aggregate 容量设为 uint 8192：total 项暂未再报错，但 found/lost 需求上升到 25585，patch 需求 125471，collision stack 需求 1852412096 bytes，仍明确丢接触。GPU 持续满载且未取得 60 步进度点，停止该失败对照；没有填造实际完成步数或 600 步报告。证据：gpu_v06_local_aggregate_fixed_partial_20261019.json / .log。

因此，“两项设为 8192 即修好”被实测否定。新增 --patch-capacity / --collision-stack-size 只提供可复跑的参数入口，**更大容量组合尚未运行验证，不能直接作为训练配置**。W3 下一步还需查初始碰撞与碰撞体复杂度，再验证预算和性能；当前主场景的旧仪器定义也仍有嵌套刚体、joint frame 等警告。没有将 v5 自动替换进 v06。

review_capacity_log.py 从外部物理日志判定溢出，验证器自身的“完成步数”不再被当成日志无错。完整场景还有机器人远程 payload 缺失，始终未做通过声明。
