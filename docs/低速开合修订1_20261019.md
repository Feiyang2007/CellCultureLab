## 2. 平衡角求根漏掉常数项 C——已修正并复算

拟合式是 `τ_g(q)=A sin q + B cos q + C`，而我上一版求根用了 `q=−ψ`（即令 C=0）。C 量级只有 4.06e-5 N·m，但平衡角正是 τ=0 那个点，C 会把根整体平移，不能省。完整解 `r0·sin(q+ψ)=−C/r0` 后：

| 量 | 值 |
| --- | --- |
| 修正后拟合根 | **0.5844938764832855 rad** |
| 你的独立复算值 | 0.5844938765 rad ✓ 逐位一致 |
| 修正前（漏 C） | 0.5840039746 rad |
| 原 3.3.0 参考 | 0.5845205177 rad |
| 与参考差 | 修正前 5.17e-4 rad → **修正后 2.66e-5 rad** |
| 拟合根处的残差 τ | 5.47e-18 N·m（数值精度内为 0） |

`scripts/recheck_lid_gravity_torque.py`（`d9e5f15117a6f339`）现在把 `with_C` / `without_C` / C 值 / 平移量 / 根处残差都写进 `mini_lid_gravity_torque_recheck.json`，谁都能复算。端点重力矩与两条界限（开盖 >0.04565、关盖 >0.07473 N·m）不受影响。

## 4. 下一轮的两层对照，判据与对齐方式先钉死

按你要求分两层、分开报，不插值、不事后调阈值：

**第一层·动力学轨迹对照。** 把本次记录的**同一条力矩序列**原样喂给两个引擎：Isaac 端直接复用 `rev1.steps.jsonl` 的 `torque_Nm`；MuJoCo 3.3.0 端按记录顺序对 lid DOF 施加同样的广义力矩，dt=1/240、积分器与源模型默认一致、初态取记录第 0 步的 `q_pre/v_pre`、限位取源 range。时间对齐：**按步号一一对齐，不重采样不插值**（两边同 dt、同步数）。误差指标（lid 单 DOF）：`max|Δq|`(rad)、`RMS|Δq|`、`max|Δv|`(rad/s)。容差（跑前定死）：`max|Δq| ≤ 1e-3 rad` 且 `max|Δv| ≤ 0.05 rad/s`。失败就报**第一个越界的步号与该步两边原始值**，不放宽、不改记录方式。

**第二层·控制器表现对照。** 两引擎各自跑同一套反馈律（同样的 ω=30、ζ=0.7、I、v_design=1.0、a_design=20、τ 饱和 0.25、同一参考梯形轨迹），比较各自的 q/v/τ 曲线与控制量：两边各自的峰值角速 ≤1.2 rad/s、离限位最小距离 ≥0.05 rad、跟踪误差 ≤10 mrad、无冲击跳变（Δv ≤ 3× 设计预期）、τ 饱和步数 = 0；两引擎轨迹间再给一次 `max|Δq| ≤ 5e-3 rad`。这一层允许差异来自求解器与控制实现，与第一层分开陈述，不许用第二层的通过去覆盖第一层的不通过。

- 动作组合（开盖→转子点动→关盖）一律标为**"关节协议测试"**，不是真实离心操作任务。
