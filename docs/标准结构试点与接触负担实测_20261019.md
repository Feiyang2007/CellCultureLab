# 标准结构试点与接触负担实测

2026-10-19。此次新增独立试点和诊断覆盖层，未替换 v5 或主场景。

## 当前结论

1. mini 已用固定底座 Articulation、真实编译惯量/质心和原生 armature 建立独立试点。与本地 MuJoCo **3.16.0 候选参考**进行八组力矩/重力轨迹对照，全部通过；不能当成上游 3.3.0 同版本验收。
2. 原先传入 update_simulation 的 dt 没有锁定 PhysicsScene 频率。在本轮修复前，1/240 秒调用下的状态每四次才更新；显式配置 240 Hz 后，转子轨迹误差从约 9.77° 降至约 0.000207°。这是测量/推进配置缺口，不应靠修改惯量或增益补偿。
3. mini 的碰撞组已还原其内部 (contype=0, conaffinity=1) 规则，运行时正反控制通过；外部接触仍有效。该过滤只覆盖单件内部，未来多个设备组成任务时仍需建立跨资产配对规则。
4. W3 有了进一步隔离证据：**去掉全部吸头、保留旧 Stations 分支仍发生配对容量溢出；再停用旧 Stations 后，剩余场景完成 120 步 GPU 仿真且无容量溢出。** 旧仪器分支是当前需要优先修复的贡献来源。尚未定位到单台仪器，也没有证明吸头在完整场景中无负担。

## mini 实现及验收边界

- 资产：assets/instruments6_pilot/centrifuge_tiangen_tgear_mini.usda。
- 场景：assets/scenes/test_mini_articulation.usda。
- 固定关节连接世界与底座；ArticulationRootAPI 位于 world_fixed；不使用运动学底座、辅助惯量刚体、注入位置驱动或额外求解迭代。
- 参考来自原始 standalone XML 的 Windows MuJoCo 3.16.0 编译数据，保留完整版本标记；与旧 3.3.0 真值核对初始位置及旋转一致，质量最大相对差约 2.95e-7。这不足以替代同版本验证。
- 八组：盖子/转子各正负 0.001 N·m 和零输入；盖子重力响应；转子额外 0.1 kg·m² armature 的控制实验。普通力矩实验 60 步，重力实验 12 步，均为 240 Hz。初态在限位内部，避免把软硬限位差异混入惯量比较。
- 启用碰撞；源 mini 内部配对本就被掩码排除，因此这些轨迹不构成碰撞任务验收。
- 全轨迹最大角度差约 0.00020737°；最大禁止位移约 5.97e-8 m。预先设定门槛为角度 0.5°、速度 0.1 rad/s、禁止位移 0.1 mm、禁止角偏差 1°。
- 原生 armature 0.1 的运行时读回为 0.10000000149。该值只用于控制实验，未把额外 armature 写进原设备资产。
- 过滤控制：两对远离设备的盒体各有 5 mm 初始重叠；同组过滤开启时 B 位移约 1.43e-8 m，关闭时约 5.002 mm；外部 D 在两种情况下均移动约 5.003 mm。这验证了过滤机制，不是插管或抓取验证。
- 源 XML 的 lid-lock 默认 inactive。已导出并在构建报告保留，**没有迁移锁盖状态机或激活后的物理行为**。

最终证据：outputs/runtime_validation/mini_articulation_comparison.json（含资产/参考哈希、全轨迹、过滤控制及明确的 original_version_matched=false）。

失败对照也保留：mini_articulation_wrong_timestep_comparison.json；mini_filter_control_failed_clear_targets.json。后者发现 ClearTargets 会暴露引用层中的过滤关系，反向控制必须用显式空目标列表阻断，修复后正反控制才同时通过。

## 导出与环境限制

新增 scripts/export_physics_reference.py，默认要求 MuJoCo 3.3.0；其他版本必须显式 --allow-version-drift 并标为候选。导出质量/惯量/惯性坐标系、关节与 DOF 参数、qpos_spring、接触掩码及例外、执行器、等式约束、插件声明和指定力矩轨迹；它不迁移 Python 任务行为。

候选数据已导出 mini、5430、5910 和恒温混匀仪。C1000、涡旋在当前 Windows 环境中未注册源 detent 插件，明确失败，未删除插件后继续转换。源 Linux libmjlab.so.3.3.0 存在；这不是“仓库缺插件”。

WSL 当前返回 E_ACCESSDENIED。同版本 Windows 依赖下载传输随后被自动审批拒绝，理由为被判定绕过受管网络代理且缺少新增授权；已停止并清理未完成的依赖文件，没有安装或修改 Isaac 的依赖。3.3.0 同版本对照保持未完成。

Isaac 测试环境还存在临时目录/缓存写入错误及退出阶段残留进程。本轮从关闭前 stdout 保存完整结果，外部复核物理日志，并只清理核对过命令行的自建测试进程。没有把进程退出码当作物理通过，也未修改分页设置。

## 复跑

在项目根目录执行；USD/Isaac 使用 D:/IsaacSim5/env/Scripts/python.exe。

```text
python -B scripts/export_physics_reference.py --source-dir <原始model/instrument目录> --names centrifuge_tiangen_tgear_mini --trials
python -B scripts/build_mini_articulation.py --reference-dir upstream/physics_reference
python -u -B scripts/compare_mini_physics.py
```

上述第一条应在原始 3.3.0 环境执行。若仅复现当前 3.16 候选，另设输出目录 upstream/physics_candidate，显式加 --allow-version-drift；构建时显式给 --reference-dir upstream/physics_candidate --allow-candidate。

运行完成后需保留 stdout 并检查物理日志；若环境无法写报告，应从 REPORT_JSON 留存。构建器检查参考哈希及原始几何/质量偏差；比较器拒绝使用构建后被改动的参考文件。

scripts/check_actuation_direction.py 和 validate_gpu_capacity.py 也已补齐 PhysicsScene 实际步频设置。旧 v5 的 21/21 仍是有效的方向/端点观察；旧报告中的 dt 仅是调用步长，不能据此宣称实际物理步频、轨迹时序或动力学等价。
