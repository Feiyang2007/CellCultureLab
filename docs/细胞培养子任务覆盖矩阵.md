## 2. 缺口按对环境完整性的影响排序（不按演示价值）

**A 类｜缺整个工位（流程的入口与出口）**
1. 生物安全柜 / 超净工作台：柜体 + **移门可升降** + 内部可放操作 + 风机/照明开关；
2. CO₂ 培养箱：门可开、**多层搁架**可放取皿、温度/CO₂ 状态量；
3. 显微镜（或至少"载物台 + 观察判读接口"，可先不做光学只做放置与判读）；
4. 细胞计数：计数板+盖玻片，或自动计数仪（样品加样 + 出数）；
5. 冷链与废弃：4℃ 冰箱/冰盒、-20℃、冻存盒、液氮罐、废液瓶与锐器盒。

判据：每类设备落地后，必须满足"门/移门能被夹爪驱动、柜内可放可取、其状态能被脚本读到"，否则只是新摆饰。

**B 类｜缺交互能力（有设备也做不完任务）**
6. **液体抽象**：体积守恒的吸/排（`liquidVolume` 之类的自定义属性 + 液位可视化），否则"吸上清/吹打/分种"全是空动作；
7. 拧盖：螺旋耦合（上游 MuJoCo 用 bolt/nut 插件，`pitch=0.003 radius≈0.0051`），USD 侧要么做旋转-平移耦合驱动，要么用两段式近似；
8. 不可见状态量：细胞密度/消化程度/污染，决定"判读类"子任务能不能有成功判定；
9. 语义标签（`SemanticsAPI`）与子任务成功判定接口——数据生成的前置。

## 5. GPU 接触容量（未解决，但已定位到可疑点）

跑仿真时 PhysX 反复报：

```
PhysX error: The application needs to increase
PxGpuDynamicsMemoryConfig::totalAggregatePairsCapacity to 1025 ...
PxGpuDynamicsMemoryConfig::foundLostAggregatePairsCapacity to 2325 ...
otherwise, the simulation will miss interactions
```

`miss interactions` 对抓取/插拔类数据是致命的（碰到了却不算接触）。两条实测要点：

1. 引擎要的是 **1025 / 2325**，而默认上限是 1024 —— **只差一点点**，属边际超限，不是容量严重不足；
2. 我按 Isaac 自己的属性名（`physxScene:gpuTotalAggregatePairsCapacity` 等，见 `isaacsim.core.api/.../physics_context.py`）把 4 项写进场景，**也**在启动后用 carb 设置 `/persistent/physics/gpu*` 设过，**两种都没能让报错消失**。

结合第 4 节新发现（PhysicsScene 在 `/physicsScene` 且无 gravity 设置），下一步该先确认"引擎实际生效的是不是这个 scene、以及这版 PhysX 到底读不读 USD 上这几个属性"，而不是继续加大数值。**这条要单独查，也要告诉师兄**——他做数据生成时同样会撞上漏接触。

## 7. 仪器可动性的真实现状（2026-10-18，两条判据各推翻一次我自己的结论）

**结论：目前六台自转仪器（`assets/instruments2/`）的可动件没有被真正仿真，"盖子能开"还没有成立。**

两条实测（都是 fresh 单轮启动，判据来自 PhysX 而不是 USD 变换）：

| 测试 | 脚本 | 结果 |
|---|---|---|
| 稳定性 | `check_settle_v3.py` | 只测到 **6/6 个顶层底座刚体**在仿真，600 帧 0 位移 → 之前我写的"稳"是**另一种假通过**：可动件（盖、转子、吊篮、旋钮）根本没进仿真图，所以"没有东西会掉"是显然的 |
| 关节驱动 | `check_joint_range.py` | **能被驱动的关节 0 / 20** |

根因是 PhysX 那 20 条 `missing xformstack reset … unpredicted results`：v1 转换器把带关节的子 body 嵌在父刚体下面，PhysX 不接受这种嵌套刚体，于是可动件被排除在仿真之外。

**已尝试并失败的两条修法**（都隔离了，别再当成可用）：
1. 往 `xformOpOrder` 塞 `xformOp:!resetXformStack!` —— 这版 USD 判它非法 op，把变换栈整个弄坏，刚体数直接掉到 0（表现就是我上一轮报的那次假通过）；
2. 压平层级（`mjcf_instrument_to_usd_v2.py` → `assets/instruments3/`）—— 嵌套刚体确实变成 0，但**几何位置错了**（5910 外形从 0.72×0.92 变成 0.77×1.47，渲染图能看到零件炸开）；我按"双重变换"改过一次，包围盒一个数都没变，说明不是它。**这个文件已判定不可用**，配套的 `test_instruments3.usda` 与截图已删除。

**下一步的具体做法（不再靠我手推矩阵）**：这台机器上 `mujoco` 是可用的（3.14），直接用它编译上游 `model/instrument/*.xml`，读取每个 body 的 `body_pos` / `body_quat` 世界位姿作为**权威真值**，再让压平后的 USD 逐 body 写这个值——这样"位置对不对"由 MuJoCo 判定，而不是我推矩阵推对了没。写完再跑 `check_joint_range.py`，判据改成：**指令目标 vs 实际转角的误差 < 20%，且被测到可驱动的关节数 ≥ 关节总数的 90%**。

在此之前，`assets/instruments2/` 只可当**带外观与碰撞的静态模型**用；主场景里师兄那台 5430（盖、转子都绑好且在仿真图内）仍是目前唯一真正可交互的仪器。
