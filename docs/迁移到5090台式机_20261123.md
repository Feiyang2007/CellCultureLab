### 对表之后确认的代价（比担心的小）

数过整个仓库：141 个脚本里 34 个要真 `SimulationApp`、27 个只吃离线 `pxr`。版本耦合点只有三类——

1. **导入名**：仓库用的已经是 `isaacsim.core.*` 新命名空间（不是 `omni.isaac.*`），
   23 处引用基本不用动。
2. **写死路径**：`isaacsim-5.1.0` 出现在 28 个文件里，但 **16 个 `.py` 中有 14 个只是文档里的用法示例**；
   真代码只有 `scripts/_pxr_env.py` 和 3 个 `.bat`。已改成：`ISAAC_ROOT` 环境变量优先 →
   自动找 pip 版 `isaacsim` 包目录 → 兜底 `D:/isaacsim-5.1.0`，并且 `extscache` 里的包名
   从写死 `+69cbf6ad...cp311` 改成按前缀取最新（6.x 是 cp312，写死必挂）。本机 5.1 复测过，输出一致。
3. **四元数序**：Lab 3.0 把 (w,x,y,z) 改成 **(x,y,z,w)**。我们目前没走 Lab 的 API，
   但判据里凡是拿四元数比朝向的地方，接 Lab 那天必须重测一遍。

真正没底的是两条，只能到那台上跑一次才知道：**6.2 的 pxr 能不能读我们这套 usda**（5.1 写的，向后兼容是应该的，
但 `SemanticsAPI` 的 schema 注册在新 Kit 里换了位置）、以及 6.2 对 v09 的接触容量默认值。
都归在下面第 2、3 步里验，不用额外做什么。

> 580.88 是 **5.1** 的验证驱动；Lab 3.0 / Sim 6.2 的 Windows 下限本来就是 580.88，

  requirements 页列的 **580.88（Windows）**；本任务 #5 当年在这台 4060 上降级也是同一件事。
- 所以那台机器**先查驱动再装 Isaac**：`nvidia-smi` 一看是 59x/60x 就先把 580.88 装上，
  否则后面所有"场景打不开/一跑就崩"的排查都会白费。
- 按规矩，安装动作由你本人点，我只给版本号和校验。

## 传什么、怎么传

**① Isaac 本体：拷安装包，不拷安装目录。**
本机还留着原始 zip：`D:\Temp\isaac-sim-standalone-5.1.0-windows-x86_64.zip`，**7.35 GB**，
sha256 记在 `D:\Temp\isaac_zip.sha256.txt`（传完在新机器上比对一次再解压）。
拷 zip 比拷 16 GB 的 `D:\isaacsim-5.1.0` 干净：不带本机的 shader/KVDB/材质缓存状态，
也比在那台重新下载省一次公网流量。
解压目标建议**同样叫 `D:\isaacsim-5.1.0`** —— 仓库里几十个脚本和文档的路径都是写死这个的，
换个位置就得改一遍。解压后先跑 `post_install.bat`（本机当年这一步没跑会缺扩展缓存）。

**② 工程本体：472 MB，但 git 里是不全的。**
`du`：`assets/` 220 MB、`outputs/` 77 MB、`scripts/` 1.7 MB、`docs/` 若干。
**坑在这里**：`.gitignore` 排除了 `*.usd / *.usda / *.obj / *.7z`，
所以 clone 出来的仓库是个"没有资产的场景"——77 个 `.usda`（含这轮刚修的三台补货资产）一个都不在 git 里。
必须整目录拷，或者单独打一个包含 `assets/` 的包。

**③ 会话记忆怎么走。**
- user 级：`C:\Users\17690\.qoder-cn\memory\`（`MEMORY.md` 索引 + 各主题 md）
- project 级：`C:\Users\17690\.qoder-cn\projects\C--Users-17690-Documents-FeiyangChen\memory\`
- 中间那串目录名是按**工程绝对路径**算出来的。新机器用户名不同或工程放别处，
  Qoder 会算出另一个名字，直接拷过去它认不到 —— 要么把工程放在同样的相对位置
  （`Documents\FeiyangChen`）并把目录名改成新机器对应的形式，要么走下面这条更稳的。
- **最不怕丢的一条**：关键结论本来就写在仓库 `docs/` 里
  （这份 + 《任务套件判据与工位交互体检_20261123.md》6A–6H）。
  到新机器开 Qoder 第一件事就是让它读这两篇，比拷记忆目录可靠，因为它是跟着 git 走的。

## 到新机器后的验收顺序（先便宜后贵，别一上来开 GUI）

> 【11-24 按 B 路线改】下面所有 `python.bat` 都换成"你那套 6.2 的 python"。
> 走 Lab 3.0 的 uv 装法就是在 `C:\Users\73\IsaacLab` 里
> `uv run --extra isaacsim python "工程路径\scripts\xxx.py" ...`；
> 离线那批（第 2 步）不吃 Kit，只要解释器能 `import isaacsim`，`_pxr_env.py` 就自己找到 extscache，
> 找不到再设 `ISAAC_ROOT` 指到 `...\site-packages\isaacsim`。

0. 先花 30 秒确认 Sim 到底装在哪（只读）：
   `Get-ChildItem C:\Users\73\isaacsim -Force`、`python -c "import isaacsim,os;print(os.path.dirname(isaacsim.__file__))"`。
   看到 `extscache\` 才算数——那批离线脚本全靠它。
1. 无头冒烟：起一个 `SimulationApp(headless=True)` 看有没有报错（6.2 首启会下扩展、要接受 EULA，慢是正常的）。
2. **纯 CPU 那批先全跑通**（这批根本不吃显卡，能证明拷贝没把资产弄坏）：
   - `survey_scene_assets.py assets/scenes/biolab_main_v09.usda`
   - `check_semantics.py --overlay assets/scenes/semantics_v09.usda --base assets/scenes/biolab_main_v09.usda`
     → 期望 488 个 prim、41 个类名、0 孤儿。**这条同时是在验 6.2 的 pxr 认不认我们的 usda 和 SemanticsAPI**，
     它挂了先别管数字对不对，先看是不是 schema 没注册。
   - `fix_stock_colliders.py`（**不加 `--write`**）
     → 期望三台都报"退化盒碰撞体 0 个（已经是好的）"。这条专门用来确认 6F 那个修复跟着拷过来了；
     要是报"1/16/22 个"，说明拷的是改前的旧资产。
3. 判据：`eval_task_goal.py --suite v01.4 --mode reachable --gpu-cap`
   （v01.4 = 摆放高度从"跨组借用"改成几何半高的那一版任务集，见 6H）。
4. 最后才开 GUI：`启动场景.bat assets/scenes/biolab_main_v09.usda`
   （11-24 起它认 `ISAAC_PY`，不设就用本机 5.1）。
